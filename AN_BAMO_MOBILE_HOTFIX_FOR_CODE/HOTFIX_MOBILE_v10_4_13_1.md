# HOTFIX — мобильный UX, v10.4.13.1

Baseline: `AN_BAMO_Command_Center_v10_4_13_Field_Measure_Restore.html`
Выходной файл: `AN_BAMO_Command_Center_v10_4_13_1_Mobile_Hotfix.html`

Два реальных бага, пойманных пользователем на телефоне Android (Chrome).
Правка — только CSS/минимальный JS в новом слое в конце `<body>`. Wrap, не rewrite. Ничего за пределами этих двух проблем не трогать.

---

## BUG 1 — Свайп вниз перезагружает страницу (pull-to-refresh)

**Симптом:** свайп вниз в верхней части экрана → Chrome перезагружает страницу → данные/состояние теряются.

**Причина:** в CSS нет `overscroll-behavior-y: none` (или `contain`) ни на `html`, ни на `body`. Chrome на Android включает pull-to-refresh по умолчанию.

**Фикс:** добавить в новый `<style>` слой:
```css
html, body {
  overscroll-behavior-y: none;
}
```
`none` отключает и pull-to-refresh, и резиновый отскок сверху/снизу — именно то, что нужно для app-подобного поведения. Горизонтальные `overscroll-behavior-x: contain` на чипах/настройках трогать не надо.

## BUG 2 — Нижняя навигация пропадает при длинном скролле

**Симптом:** при скролле вниз на длинных страницах нижняя панель (`mobile-nav`) иногда «отваливается» — видна пустота там, где должны быть кнопки; помогает только обновление страницы.

**Причина (из кода):** `.mobile-nav { position: fixed; bottom: 0 }` — архитектурно правильно. Но на Android Chrome при очень длинном `body`-скролле (`body` не ограничен — `min-height: 100%`, не `height: 100%`) compositing-слой навигации иногда «теряется» при появлении/скрытии адресной строки браузера. Нет GPU-hint'а, нет `will-change`.

**Фикс — два шага:**

### Шаг A: GPU-hint на навигацию (обязательно)
Добавить в новый `<style>`:
```css
.mobile-nav {
  will-change: transform;
  -webkit-backface-visibility: hidden;
  backface-visibility: hidden;
  transform: translateZ(0);
}
```
`transform: translateZ(0)` выталкивает элемент на отдельный compositor-слой — он перестаёт «теряться» при перерисовках из-за адресной строки браузера.

### Шаг B: изолировать скролл контента (желательно, но не ломать layout)
Страницы длинные, body прокручивается целиком. Правильный app-shell: шапка + навбар фиксированы, контент скроллится в своём контейнере. Но переделывать HTML-структуру — это большая задача и риск регрессий. Поэтому:

**Минимальный вариант Б (достаточно для хотфикса):** добавить к `html`:
```css
html {
  height: 100%;
  overflow: hidden;
}
body {
  height: 100%;
  overflow-y: auto;
  -webkit-overflow-scrolling: touch;
}
```
Это переключает основной скролл с `window` на `body` — поведение одинаковое для пользователя, но `position:fixed` элементы ведут себя стабильнее (они позиционируются относительно viewport, а не страницы). 

⚠️ После этого изменения обязательно проверь:
- что `position:sticky` на `.topbar` (строка 36) продолжает работать (sticky на body-scroll работает так же);
- что modal (`position:fixed; inset:0`) по-прежнему покрывает весь экран;
- что `.numeric-sheet` (position:fixed; bottom:0) всплывает корректно;
- что `.toast-wrap` (position:fixed) видна.

Если что-то из этого сломалось — откати шаг Б, оставь только шаг А + BUG 1. Шаг А один уже значительно улучшает ситуацию.
