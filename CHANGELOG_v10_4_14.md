## БЛОК B — Цикл закрытия сделки

Документные функции лежат в замыкании (не глобальны), поэтому Block B **наблюдает модалку документа** (MutationObserver) и **форвардит клики на существующие кнопки** панели действий (`docShare`/`docSaveHtml`/`docMarkSent`/`docPrint`). `renderRequest` глобальна — обёрнута для чек-листа и бэкапа. Namespace `data-v1414b-act` (чтобы не конфликтовать с обработчиком Block A).

### B1 — Скачать PDF
Кнопка «Скачать PDF» в панели действий документа → `window.print()` (заголовок документа подставляется в имя файла). Без CDN — печать в PDF средствами браузера, ничего не виснет офлайн.

### B2 — Отправить: bottom-sheet
Кнопка «Отправить» открывает нижний лист с вариантами: 📤 Поделиться · 💾 Скачать HTML · 🖨️ Печать / PDF · ✅ Отметить отправленным. Каждый вариант форвардит на штатное действие документа. Лист — отдельный fixed-компонент со стилем как `numeric-sheet`.

### B3 — Чек-лист готовности на «Заявке»
В карточку «Проверка проекта» инжектируется state-driven чек-лист: КП сформировано / КП отправлено / Аванс получен / ТЗ цеху отправлено / Цвет зафиксирован, плюс баннер «Готово к запуску» (зелёный, все ✓) или «Есть незакрытые пункты» (амбер). Считается из `documentLog`, `payments`, `colorPending`.

### B4 — Подпись клиента пальцем
В документе «Акт приёмки» инжектируется `<canvas>` с рисованием pointer-событиями (touch+mouse), кнопки «Очистить» / «Сохранить подпись». Сохраняется в `state.clientSignature` (PNG dataURL), при повторном открытии показывается как `<img>` с кнопкой «Подписать заново». Backfill в `ensureV1414B`.

### B5 — Бэкап в один тап + возраст
На «Заявке» (карточка «Версии / слепки») кнопка «Бэкап ⬇» → выгрузка JSON всего проекта + `state.lastBackupAt`. Под кнопкой «Последний бэкап: сегодня / N дн. назад». Если > 7 дней — кнопка и подпись амбер.
